\section{Elección de tecnologías}
\label{sec:justificacion}
Tras analizar las diferentes tecnologías disponibles para el desarrollo de la aplicación en el \autoref{cap:analisis_tecnologias}, he decidido utilizar \textbf{Flutter} como tecnología front-end 
porque presenta varias ventajas significativas frente al resto de alternativas. Una de las razones más destacadas es su capacidad de desarrollo multiplataforma, 
que permite crear una única base de código que se ejecuta tanto en Android, como en iOS, web y aplicaciones de escritorio, lo que ahorra tiempo 
y esfuerzo en comparación con desarrollar código nativo para cada plataforma por separado. Además, Flutter ofrece un rendimiento cercano al 
de las aplicaciones nativas, gracias a su motor gráfico Dart, que se compila en código nativo. Otra ventaja es el sistema de Hot Reload, que permite 
a los desarrolladores visualizar los cambios en tiempo real, sin tener que recompilar por completo. Tiene también una enorme capacidad de 
personalización, simplificando la tarea. Además, al estar respaldado por Google,, recibe soporte continuo.



En cuanto a la tecnología back-end, he decidido utilizar \textbf{Firebase} porque ofrece una serie de ventajas que lo hacen destacar frente a las
otras alternativas. Para empezar, Firebase proporciona un backend completo, lo que significa que no es necesario gestionar servidores ni 
preocuparse por la configuración y el mantenimiento. La integración de la autenticación de usuarios es también uno de sus puntos fuertes, ya que 
Firebase Auth facilita la implementación de los mismos. Otra razón para elegir Firebase es su base de datos en tiempo real, que permite 
sicronización instantánea de datos. Además, tiene una gran integración con servicios de Google, optimizando la monitorización del rendimiento.


\section{Iteracciones de desarrollo}
\label{sec:iteracciones}
El desarrollo de la aplicación se ha estructurado en varias iteracciones, siguiendo una metología iterativa. 
En cada iteración se va a desarrollar una serie de funcionalidades, asociados a los requisitos especificados anteriormente. 
A continuación se detallan las iteracciones que se han llevado a cabo para el desarrollo de la aplicación:

\subsection{Iteración 1}

En esta primera iteracción se van a desarrollar los siguientes requisitos:
\begin{itemize}
    \item {\hyperref[req:RF01]{RF\_01}}: Registro.
    \item {\hyperref[req:RF02]{RF\_02}}: Inicio de sesión.
    \item {\hyperref[req:RF03]{RF\_03}}: Inicio de sesión con Google.
    \item {\hyperref[req:RF04]{RF\_04}}: Cerrar sesión.
    \item {\hyperref[req:RF05]{RF\_05}}: Ver datos de usuario.
    \item {\hyperref[req:RF06]{RF\_06}}: Editar datos de usuario.
    \item {\hyperref[req:RF07]{RF\_07}}: Crear hogar.
    \item {\hyperref[req:RF08]{RF\_08}}: Unirse a un hogar.
    \item {\hyperref[req:RF09]{RF\_09}}: Abandonar hogar.
    \item {\hyperref[req:RF10]{RF\_10}}: Ver datos del hogar.
    \item {\hyperref[req:RF11]{RF\_11}}: Editar hogar.
\end{itemize}

Antes de la implementación de los requisitos mencionados anteriomente es necesario realizar una configuración inicial del proyecto.
Para ello, lo primero es configurar el entorno de desarrollo, asegurando que todas las herramieentas necesarias estén correctamente 
instaladas. Se utiliza Visual Studio Code como editor principal y se instala Flutter junto con las dependecias necesarias. 
También es necesario configurar un emulador para poder realizar las pruebas de la aplicación posteriormente. 

Una vez configurado el entorno de desarrollo, se procede a la creación de un nuevo proyecto de Flutter.
Se configura un sistema de control de versiones con Git y se sube el código a un repositorio en GitHub para llevar un seguimiento. 

Otra de las tareas a realizar antes de empezar con la implementación de los requisitos es la configuración de Firebase.
Para ello se crea un nuevo proyecto en Firebase y se configuran los servicios necesarios (como Firebase Auth para la autenticación de usuarios y Firebase Firestore para almacenar datos).

Por último antes de empezar con la implementación de los requisitos, se realizan pruebas de conexion entre la app y Firebase para confirmar
que la base de datos está correctamente configurada y que la aplicación puede comunicarse con ella sin problemas. 

Al usar Flutter como tecnología de desarrollo, se está cumpliendo el {\hyperref[req:RNF_04]{RNF\_04}} - Compatibilidad, 
ya que Flutter permite desarrollar aplicaciones multiplataforma que se ejecutan en Android e iOS. Además, Flutter también 
es compatible con aplicaciones web y de escritorio, lo que amplía aún más el alcance de la aplicación y asegura que pueda 
ser utilizada en una variedad de dispositivos y sistemas operativos. Esto no solo mejora la experiencia del usuario al 
permitirle acceder a la aplicación desde diferentes plataformas, sino que también optimiza los recursos de desarrollo al 
reducir la necesidad de mantener bases de código separadas para cada plataforma.

Firebase contribuye al cumplimiento del {\hyperref[req:RNF_01]{RNF\_01}} - Seguridad, gracias a las características de seguridad que ofrece. 
En primer lugar, Firebase Auth proporciona un sistema de autenticación de usuarios, permitiendo implementar métodos de inicio de sesión seguros, 
como autenticación mediante correo electrónico y contraseña, o autenticación con proveedores externos como Google. 

Además, Firebase Firestore incluye reglas de seguridad que permiten definir políticas de acceso a los datos almacenados en la base de datos.
Tambien utiliza conexiones seguras para la comunicación entre la aplicación y los servicios de backend, asegurando que los datos transmitidos 
estén cifrados y protegidos.

Para los datos relacionados con los usuarios y los hogares, se crearán colecciones en Firebase Firestore para almacenar la información de forma estructurada.

\paragraph{Pantalla de registro}
\parbox{\textwidth}{ 
   
}

Esta pantalla se ha implementado con la clase \textit{RegistrationPage} que permite a los usuarios crear una nueva cuenta en la aplicación. Esta clase
maneja todo el proceso de registro, tanto con email y contraseña como mediante Google.

Las funciones principales de esta clase son: 
\begin{itemize}
    \item \textbf{initState :} Este método se encarga de preparar las animaciones iniciales que hacen aparecer gradualmente el contenido cuando se abre la pantalla, creando una transición para el usuario.
    \item \textbf{\_register :} Es la función encargada del registro con email y contraseña. Verfica primero que todos los campos estén correctamente completados, luego intenta crear la cuenta en Firebase. Si tiene éxito, guarda los datos adicionales del usuario y envía un correo de verificación.
    \item \textbf{\_signInWithGoogle :} Gestiona el registro alternativo mediante una cuenta de Google. Inicia el proceso de autenticación con Google y si es un nuevo usuario crea automáticamente su perfil en la base de datos.
    \item \textbf{\_createUserProfile :} Guarda la información del usuario (nombre y apellidos) en Firestore después de crear una cuenta exitosamente, asociándola al ID único.
    \item \textbf{\_showRegistrationSuccessDialog :} Muestra un cuadro de diálogo cuando el registro se completa correctamente. Ofrece opciones para volver al inicio de sesión o reenviar el correo de verificación si es necesario.
    \item \textbf{\_parseAuthError :} Traduce los códigos de error técnicos de Firebase en mensajes comprensibles para el usuario.
\end{itemize}

\paragraph{Pantalla de inicio de sesión}
\parbox{\textwidth}{

Esta pantalla se ha implementado con la clase \textit{SignInEmail} que permite a los usuarios iniciar sesión en la aplicación. En esta pantalla, 
se puede iniciar sesión con email y contraseña o mediante Google.

Las funciones principales de esta clase son:

\begin{itemize}
    \item \textbf{initState :} Este método se ejecuta al iniciar la pantalla. En ella se establece una animación que hace que el contenido aparezca de forma gradual cuando se abre la pantalla.
    \item \textbf{dispose :} Se encarga de liberar los recursos utilizados.
    \item \textbf{\_signIn :} Este método se ejecuta cuando el usuario intenta iniciar sesión con su correo y contraseña. Verifica las credenciales con Firebase y luego decide a qué pantalla debe dirigirse según si el usuario pertenece o no a un hogar.

    \item \textbf{\_handleAuthError :} Es el método que decide a qué pantalla se envía al usuario después de una autenticación exitosa. Si su correo no está verificado, muestra un díalago informativo. Si ya está verificado, revisa si pertenece a un hogar para ver a qué pantalla se envía.
    \item \textbf{\_handleAuthError :} Se encarga de interpretar y mostrar mensajes claros de error cuando el inicio de sesión falla.
    \item \textbf{\_showEmailNotVerifiedDialog :} Muestra un cuadro de diálogo cuando el usuario intenta iniciar sesión sin hacer verificado su correo.
\end{itemize}

\paragraph{Pantalla de ver datos de hogar y usuario}
\parbox{\textwidth}{ 
   
}

Esta pantalla se ha immplentado con la clase \textit{ProfileScreen} que representa el perfil de usuario dentro de la aplicación. Muestra la información personal y 
del hogar al que pertenece el usuario. Su finalidad es mostrar la información personal y del hogar al que pertenece el usuario, así como 
permitirle editar sus datos, gestionar el nombre del hogar, ver a los miembros con los que convive, y realizar acciones como abandonar el hogar o cerrar sesión. 



Entre sus funciones destacadas se encuentran:

\begin{itemize}
    \item \textbf{initState :} Este método se ejecuta cuando se abre la pantalla. Inicializa el usuario actual y llama a otro método para cargar sus datos desde la base de datos.
    \item \textbf{\_loadProfileData :} Carga la información del usuario desde Firebase, incluyendo su nombre, apellidos y correo. Luego busca el hogar al que pertenece y obtiene su nombre, código y los nombres de los demás miembros del hogar.
    \item \textbf{\_updateProfile :} Permite guardar cambios en los datos del usuario, actualizandolos en la base de datos.  
    \item \textbf{\_showEditProfileModal :} Muestra un formulario en la parte inferior de la pantalla donde el usuario puede modificar sus datos.
    \item \textbf{\_buildProfileHeader :} Construye la parte superior de la pantalla, donde se muestra el nombre y apellidos del usuario y su correo.
    \item \textbf{\_buildProfileContent :} Genera el contenido del perfil debajo del encabezado. Incluye las secciones de configuración del hogar, preferencias y botones de accion.
    \item \textbf{\_buidEditableHomeNameItem :} Muestra el nombre del hogar junto a un botón para editarlo.
    \item \textbf{\_updateHomeName :} Guarda en la base de datos el nuevo nombre del hogar, si el usuario lo modifica.
    \item \textbf{\_showEditHomeModal :} Abre un formulario donde se puede cambiar el nombre del hogar.
    \item \textbf{\_buildSectionCard :} Crear una tarjeta que agrupa secciones dentro del perfil.
    \item \textbf{\_buildInfoItem :} Muestra un ítem de información dentro de una sección.
    \item \textbf{\_buildMembersList :} Muestra una lista con los nombres de los demás miembros del hogar.
    \item \textbf{\_buildSwitchItem :} Crea un interruptor que permite activar o desactivar la opción de recibir notificaciones.
    \item \textbf{\_buildActionItem :} Genera un ítem de acción dentro de una sección, como cerrar sesión o abandonar el hogar.
    \item \textbf{\_confirmarAbandonoHogar :} Muestra un cuadro emergente que pregunta al usuario si realmente desea abandonar el hogar.
    \item \textbf{\_confirmarCerrarSesión :} Muestra un cuadro emergente que pregunta al usuario si realmente desea cerrar sesión.
    \item \textbf{\_abandonarHogar :} Elimina al usuario de la lista de miembros del hogar.
\end{itemize}

\paragraph{Pantalla para participar en un hogar}

La clase de esta pantalla se llama \textit{ConenctHomeScreen} y esta diseñada para que un usuario se conecte a un hogar dentro

    \item \textbf{\_buildCustomSnackBar :} Muestra un mensaje para informar al usuario si el código es incorrecto o si se ha unido correctamente.
    \item \textbf{\_joinHomeWithCode :} Es la función que se encarga de validar el código introducido por el usuario.

\subsubsection{Revisión de la iteracción}
La aplicación ha sido probada por un usuario real, una mujer de 23 años, que comparte piso con otras tres personas.
Durante todas las iteraciones se va a contar con su colaboración para realizar pruebas de funcionalidad y obtener
nuevas mejoras.

\paragraph{Registro}

\parbox{\textwidth}{ 
   
}

El proceso de registro fue realizado con éxito por la usuaria, quien pudo crear su cuenta sin problemas. Sin 
embargo, depués de registrarse, la aplicación muestra un mensaje en la parte inferior indicando 
que debe verificar su correo y volver a iniciar sesión, pero la usuaria indicó que el mensaje no era claro y 
además aparecia durante un tiempo muy corto, lo que dificultaba su lectura.

\paragraph{Inicio de sesión}
\parbox{\textwidth}{ 
   
}

Después de indicarle a la usuaria lo que tenía que hacer después de registrarse, pudo iniciar sesión sin problemas.

\paragraph{Crear hogar}
\parbox{\textwidth}{ 
   
}

La usuaria tuvo algunas dificultades para crear un hogar, ya que el texto de ejemplo que aparece en el campo de
nombre del hogar no era claro por tanto no sabía que tenía que escribir ahí. Después pudo crear el hogar sin problemas.

\paragraph{Visualización y edición de datos de usuario y hogar}
\parbox{\textwidth}{ 
   
}

La usuaria no tuvo ningún problema a la hora de identificar donde ver sus datos y los de su hogar, supo cómo 
editarlos. Lo único que comentó era que le resulta complicado encontrar como editar los datos de su hogar.

\paragraph{Abandonar hogar y unirse a otro hogar}
\parbox{\textwidth}{ 
   
}

La usuaria puedo abandonar sin problemas su hogar y unirse a otro hogar, mediante el código que le proporcionaron.

\paragraph{Cerrar sesión}
\parbox{\textwidth}{ 
   
}

La usuaria pudo cerrar sesión sin problemas, pero le gustaría que la aplicación le preguntara si realmente quiere cerrar sesión, para 
evitar cerrar sesion por error.

\subsubsection{Pruebas de funcionalidad}

Para probar la implementación que se ha realizado se ha llevado a cabo una serie de pruebas de funcionalidad.

\begin{itemize}
    \item Comprobación de la creación de una nueva tarea. Esto incluye que la tarea se almacene correctamente en la base de datos con los datos correctos y que se muestre en la intefaz de tareas.
    \item Comprobación de la visualización de la planificación semanal. Esto incluye que las tareas semanales se muestren correctamente en la interfaz de tareas y que se actualicen al seleccionar un día específico.
    \item Comprobación de la edición de una tarea.
    \item Comprobación de la eliminación de una tarea.
    \item Comprobación de la visualización de los datos de una tarea.
    \item Comprobación de la visualización del calendario de tareas. Esto incluye comprobar que todas las tareas semanales y puntuales se muestren correctamente en el calendario y que se actualicen al seleccionar un día específico.
    \item Comprobación de marcar una tarea como realizada.
    \item Comprobación de la creación de una lista de la compra. Esto incluye que la lista se almacene correctamente en la base de datos y que se muestre en la interfaz de listas de la compra.
    \item Comprobación de la visualización de los productos de la lista de la compra. Esto incluye que todos los productos se muestren correctamente en la interfaz de productos de la lista de la compra.
    \item Comprobación de la creación de un producto en la lista de la compra. Esto incluye que el producto se almacene correctamente en la base de datos y que se muestre en la interfaz de productos de la lista de la compra.
    \item Comprobación de cambiar la cantidad de un producto en la lista de la compra.
    \item Comprobación de la eliminación de un producto de la lista de la compra.
    \item Comprobación de marcar un producto como comprado. 
    \item Comprobación de la eliminación de una lista de la compra.
\end{itemize}

\subsubsection{Revisión de la iteracción}

La aplicación ha sido probada por la misma usuaria que en la iteracción anterior. Ha probado todas las funcionalidades nuevas que se han implementado y 
las mejoras implementadas con los comentarios que realizó en la iteracción anterior.

\paragraph{Crear una tarea}

\parbox{\textwidth}{ 
   
}

La usuaria pudo crear una tarea sin problemas, pero le gustaría que la aplicación le permitiera elegir el día 
de la semana en el que se va a realizar la tarea (en caso de que sea semanal) y en el caso de no saber el día de la semana 
en el que se va a realizar, que se asigne automáticamente a todos los días de la semana. 


\paragraph{Consultar planificación semanal}
\parbox{\textwidth}{ 
   
}

La usuaria pudo consutar la planificación semanal sin problemas, pero le costó averiguar que esa pantalla mostraba solo las tareas para la semana 
actual y que si quería ver las tareas de otras semanas, tenía que ir al calendario.


\paragraph{Visualización, edición y eliminación de tareas}
\parbox{\textwidth}{ 
   
}

La usuaria no tuvo ningún problema a la hora de ver, editar y eliminar tareas y comentó que la interfaz era muy intuitiva y fácil de usar.


\paragraph{Visualización del calendario de tareas}
\parbox{\textwidth}{ 
   
}

La usuaria no tuvo ningún problema a la hora de ver el calendario de tareas, entendió perfectamente como funcionaba, 
pero indicó que le gustaría que la aplicación le mandará recordatorios de las tareas que tiene que realizar.


\paragraph{Crear lista de la compra, añadir productos y eliminar productos}
\parbox{\textwidth}{ 
   
}

La usuaria pudo crear una lista, añadir productos, eliminarlos, cambiar la cantidad de un producto y marcarlo como comprado sin problemas. 
Estuvo muy satisfecha con la interfaz y el diseño de la aplicación, ya que le resultó muy intuitivo y fácil de usar.
