En este capítulo se va detallar el proceso de desarrollo de la aplicación, explicando las tecnologías y usadas y como

\section{Elección de tecnologías}
\label{sec:justificacion}
Tras analizar las diferentes tecnologías disponibles para el desarrollo de la aplicación en el \autoref{cap:analisis_tecnologias}, he decidido utilizar \textbf{Flutter} como tecnología front-end 
porque presenta varias ventajas significativas frente al resto de alternativas. Una de las razones más destacadas es su capacidad de desarrollo multiplataforma, 
que permite crear una única base de código que se ejecuta tanto en Android, como en iOS, web y aplicaciones de escritorio, lo que ahorra tiempo 
y esfuerzo en comparación con desarrollar código nativo para cada plataforma por separado. Además, Flutter ofrece un rendimiento cercano al 
de las aplicaciones nativas, gracias a su motor gráfico Dart, que se compila en código nativo. Otra ventaja es el sistema de Hot Reload, que permite 
a los desarrolladores visualizar los cambios en tiempo real, sin tener que recompilar por completo. Tiene también una enorme capacidad de 
personalización, simplificando la tarea. Además, al estar respaldado por Google,, recibe soporte continuo.



En cuanto a la tecnología back-end, he decidido utilizar \textbf{Firebase} porque ofrece una serie de ventajas que lo hacen destacar frente a las
otras alternativas. Para empezar, Firebase proporciona un backend completo, lo que significa que no es necesario gestionar servidores ni 
preocuparse por la configuración y el mantenimiento. La integración de la autenticación de usuarios es también uno de sus puntos fuertes, ya que 
Firebase Auth facilita la implementación de los mismos. Otra razón para elegir Firebase es su base de datos en tiempo real, que permite 
sicronización instantánea de datos. Además, tiene una gran integración con servicios de Google, optimizando la monitorización del rendimiento.


\section{Iteracciones de desarrollo}
\label{sec:iteracciones}
El desarrollo de la aplicación se ha estructurado en varias iteracciones, siguiendo una metología iterativa. 
En cada iteración se va a desarrollar una serie de funcionalidades, asociados a los requisitos especificados anteriormente. 
A continuación se detallan las iteracciones que se han llevado a cabo para el desarrollo de la aplicación:

\subsection{Iteración 1}

En esta primera iteracción se van a desarrollar los siguientes requisitos:
\begin{itemize}
    \item {\hyperref[req:RF01]{RF\_01}}: Registro.
    \item {\hyperref[req:RF02]{RF\_02}}: Inicio de sesión.
    \item {\hyperref[req:RF03]{RF\_03}}: Inicio de sesión con Google.
    \item {\hyperref[req:RF04]{RF\_04}}: Cerrar sesión.
    \item {\hyperref[req:RF05]{RF\_05}}: Ver datos de usuario.
    \item {\hyperref[req:RF06]{RF\_06}}: Editar datos de usuario.
    \item {\hyperref[req:RF07]{RF\_07}}: Crear hogar.
    \item {\hyperref[req:RF08]{RF\_08}}: Unirse a un hogar.
    \item {\hyperref[req:RF09]{RF\_09}}: Abandonar hogar.
    \item {\hyperref[req:RF10]{RF\_10}}: Ver datos del hogar.
    \item {\hyperref[req:RF11]{RF\_11}}: Editar hogar.
\end{itemize}

Antes de la implementación de los requisitos mencionados anteriomente es necesario realizar una configuración inicial del proyecto.
Para ello, lo primero es configurar el entorno de desarrollo, asegurando que todas las herramieentas necesarias estén correctamente 
instaladas. Se utiliza Visual Studio Code como editor principal y se instala Flutter junto con las dependecias necesarias. 
También es necesario configurar un emulador para poder realizar las pruebas de la aplicación posteriormente. 

Una vez configurado el entorno de desarrollo, se procede a la creación de un nuevo proyecto de Flutter.
Se configura un sistema de control de versiones con Git y se sube el código a un repositorio en GitHub para llevar un seguimiento. 

Otra de las tareas a realizar antes de empezar con la implementación de los requisitos es la configuración de Firebase.
Para ello se crea un nuevo proyecto en Firebase y se configuran los servicios necesarios (como Firebase Auth para la autenticación de usuarios y Firebase Firestore para almacenar datos).

Por último antes de empezar con la implementación de los requisitos, se realizan pruebas de conexion entre la app y Firebase para confirmar
que la base de datos está correctamente configurada y que la aplicación puede comunicarse con ella sin problemas. 

Al usar Flutter como tecnología de desarrollo, se está cumpliendo el {\hyperref[req:RNF_04]{RNF\_04}} - Compatibilidad, 
ya que Flutter permite desarrollar aplicaciones multiplataforma que se ejecutan en Android e iOS. Además, Flutter también 
es compatible con aplicaciones web y de escritorio, lo que amplía aún más el alcance de la aplicación y asegura que pueda 
ser utilizada en una variedad de dispositivos y sistemas operativos. Esto no solo mejora la experiencia del usuario al 
permitirle acceder a la aplicación desde diferentes plataformas, sino que también optimiza los recursos de desarrollo al 
reducir la necesidad de mantener bases de código separadas para cada plataforma.

Firebase contribuye al cumplimiento del {\hyperref[req:RNF_01]{RNF\_01}} - Seguridad, gracias a las características de seguridad que ofrece. 
En primer lugar, Firebase Auth proporciona un sistema de autenticación de usuarios, permitiendo implementar métodos de inicio de sesión seguros, 
como autenticación mediante correo electrónico y contraseña, o autenticación con proveedores externos como Google. 

Además, Firebase Firestore incluye reglas de seguridad que permiten definir políticas de acceso a los datos almacenados en la base de datos.
Tambien utiliza conexiones seguras para la comunicación entre la aplicación y los servicios de backend, asegurando que los datos transmitidos 
estén cifrados y protegidos.

Para los datos relacionados con los usuarios y los hogares, se crearán colecciones en Firebase Firestore para almacenar la información de forma estructurada.

Esta pantalla se ha implementado con la clase \textit{RegistrationPage} que permite a los usuarios crear una nueva cuenta en la aplicación. Esta clase

\subsubsection{Base de datos}

En esta primera iteracción ha sido necesario crear dos colecciones en la base de datos de Firebase, 
una para los usuarios y otra para los hogares. 

Para la colección de \textbf{usuarios} se ha creado la siguiente estructura:
\begin{itemize}
    \item \textbf{nombre}: Es el nombre que indica el usuario al registrarse.
    \item \textbf{apellidos}: Son los apellidos que indica el usuario al registrarse.
\end{itemize}

El resto de datos como el email y la contraseña se almacenan en Firebase Auth, por lo que no es necesario almacenarlos en la base de datos.
El usuario se identifica por su ID único que genera Firebase Auth al registrarse, por tanto si queremos sacar datos adicionales del usuario como el correo electrónico,
que no tenemos almacenado en la base de datos, se puede hacer una consulta a Firebase Auth a través del ID y obtenerlo.

Para la colección de \textbf{hogar} se ha creado la siguiente estructura: 
\begin{itemize}
    \item \textbf{nombre:} Es el nombre que indica el usuario al crear el hogar.
    \item \textbf{codigo:} Es el código único que se genera al crear el hogar.
    \item \textbf{miembros:} Es un array que contiene los ID de los usuarios que pertenecen a ese hogar.
    \item \textbf{fechaCreacion:} Es la fecha en la que se creó el hogar
\end{itemize}

\subsubsection{Revisión de la iteracción}
La aplicación ha sido probada por un usuario real, una mujer de 23 años, que comparte piso con otras tres personas.
Durante todas las iteraciones se va a contar con su colaboración para realizar pruebas de funcionalidad y obtener
nuevas mejoras.

\paragraph{Registro}

\parbox{\textwidth}{ 
   
}

El proceso de registro fue realizado con éxito por la usuaria, quien pudo crear su cuenta sin problemas. Sin 
embargo, depués de registrarse, la aplicación muestra un mensaje en la parte inferior indicando 
que debe verificar su correo y volver a iniciar sesión, pero la usuaria indicó que el mensaje no era claro y 
además aparecia durante un tiempo muy corto, lo que dificultaba su lectura.

\paragraph{Inicio de sesión}
\parbox{\textwidth}{ 
   
}

Después de indicarle a la usuaria lo que tenía que hacer después de registrarse, pudo iniciar sesión sin problemas.

\paragraph{Crear hogar}
\parbox{\textwidth}{ 
   
}

La usuaria tuvo algunas dificultades para crear un hogar, ya que el texto de ejemplo que aparece en el campo de
nombre del hogar no era claro por tanto no sabía que tenía que escribir ahí. Después pudo crear el hogar sin problemas.

\paragraph{Visualización y edición de datos de usuario y hogar}
\parbox{\textwidth}{ 
   
}

La usuaria no tuvo ningún problema a la hora de identificar donde ver sus datos y los de su hogar, supo cómo 
editarlos. Lo único que comentó era que le resulta complicado encontrar como editar los datos de su hogar.

\paragraph{Abandonar hogar y unirse a otro hogar}
\parbox{\textwidth}{ 
   
}

La usuaria puedo abandonar sin problemas su hogar y unirse a otro hogar, mediante el código que le proporcionaron.

\paragraph{Cerrar sesión}
\parbox{\textwidth}{ 
   
}

La usuaria pudo cerrar sesión sin problemas, pero le gustaría que la aplicación le preguntara si realmente quiere cerrar sesión, para

\subsubsection{Base de datos}

Como resultado de la implementación de esta iteracción, se han creado las colecciones tareas, lista y producto en la base de datos de Firestore.

Para la colección de \textbf{tareas} se ha crado la siguiente estructura:

\begin{itemize}
    \item \textbf{asignados}: Contiene los usuarios asignados a la tarea (en caso de que sea semanal).
    \item \textbf{año}: Almacena el año en el que se va a realizar la tarea.
    \item \textbf{completada}: Almacena el estado de la tarea (si ha sido completada o no).
    \item \textbf{descripcion}: Es la descripción de la tarea.
    \item \textbf{fecha}: Es la fecha en la que se va a realizar la tarea (en caso de que sea puntual).
    \item \textbf{fechaActualizacion}: En caso de que la tarea se modifique, almacena la fecha de la última modificación.
    \item \textbf{fechaCreacion}: Almacena la fecha en la que se creó la tarea.
    \item \textbf{mes}: Es el mes en el que se va a realizar la tarea. (en caso de que sea semanal).
    \item \textbf{semanas:} Es una lista con las semanas del mes en las que se va a realizar la tarea (en caso de que sea semanal).
    \item \textbf{tipo}: El tipo de tarea (semanal o puntual).
    \item \textbf{titulo}: Es el título de la tarea.
    \item \textbf{usuarioId}: Es el id del usuario que ha creado la tarea.
\end{itemize}

La colección de \textbf{lista} almacena la siguiente información:

\begin{itemize}
    \item \textbf{esGrupal}: Es un booleano que almacena true en caso de que la lista sea compartida con el hogar y false en caso de que sea individual.
    \item \textbf{nombre}: Es el nombre de la lista.
    \item \textbf{usuario}: Es el id de los usuarios que participan en la lista. 
\end{itemize}


Por último, la colección de \textbf{producto} almacena la siguiente información:

\begin{itemize}
    \item \textbf{cantidad}: Es la cantidad del producto que se va a comprar.
    \item \textbf{comprado}: Es un booleano que almacena true en caso de que el producto haya sido comprado y false en caso de que no lo haya sido.
    \item \textbf{fechaComprado}: Si se ha comprado el producto, almacena la fecha en la que se compró.
    \item \textbf{fechaCreacion}: Es a l fecha en la que se creó el producto.
    \item \textbf{icono}: Es el icono del producto.
    \item \textbf{listaId}: Es el id de la lista a la que pertenece el producto.
    \item \textbf{nombre}: Es el nombre del producto.
\end{itemize}

\paragraph{Pantalla de gastos}

\parbox{\textwidth}{ 
   
}

La clase principal de esta pantalla se llama GastosScreen y se encarga de gestionar los gastos compartidos en un hogar, permite a los usuarios añadir, editar y eliminar gastos y además consultar el balance de deudas personales de cada miembro del hogar. 
La pantalla está dividida en dos pestañas principales, una para ver todos los gastos registrados y otra para ver las deudas pendientes. 
Los datos se organizan por fecha, y cada gasto incluye el nombre, el pagador, los participantes y el importe correspondiente a cada uno. 
Además, las deudas se actualizan automáticamente cada vez que se registra o elimina un gasto.

Los métodos que componen esta pantalla son: 

\begin{itemize}
    \item \textbf{initState :} Inicializa la pantalla y carga algunos datos iniciales.
    \item \textbf{dispose :} Se encarga de liberar recursos cuando la pantalla se destruye.
    \item \textbf{\_cargarDatosHogar :} Busca y carga los fatos del hogar al que pertenece el usuario.
    \item \textbf{\_cargarNombresMiebres :} A través de los IDs de los miembros del hogar, busca en la base de datos y carga los nombres de los miembros del hogar.
    \item \textbf{\_mostrarModalAgregarGasto :} Abre un formulario para crear o editar un gasto. Permite introducir el título, monto, fecha, quién lo pagó y quiénes deben pagar. Calcula automáticamente el monto dividido entre los participantes.
    \item \textbf{\_eliminarGasto :} Elimina un gasto de la base de datps y llama a la función correspondiente para ajustar las deudas.
    \item \textbf{\_mostrarConfirmacionEliminar :} Muestra un cuadro de diálogo para confirmar la eliminación de un gasto.
    \item \textbf{\_mostrarDetalleGasto :} Abre un modal con todos los detalles del gasto seleccionado.
    \item \textbf{\_buildGastosTab :} Construye la pestaña de gastos, mostrando una lista de todos los gastos registrados, agrupados por fecha y también un resumen con el total de gastos y los del usuario.
    \item \textbf{\_buildGastosCard :} Crea una tarjeta para cada gasto. Mostrando el título, el monto, quién lo pagó y si el usuario es uno de los participantes.
    \item \textbf{\_buildDetailCard :} Muestra pequeños bloques de información con algunos detalles de los gastos.  
\end{itemize}

\paragraph{Pantalla principal de la aplicación}
\parbox{\textwidth}{ 
   
}

La clase principal de este archivo es \textit{HomePage} y representa la pantalla de inicio de la aplicación. Esta pantalla 
ofrece un visión general de todo lo que el usuario puede hacer en la aplicación, tareas pendientes, deudas compartidas y productos en la lista de la compra.
Funciona como un panel central donde el usuario puede consultar resumenes y acceder a las diferentes funcionalidades de la aplicación.


Las funciones que componen esta pantalla son: 

\begin{itemize}
    \item \textbf{initState :} Se ejecuta al abrir la pantalla y carga los datos iniciales del hogar, productos, deudas y tareas.
    \item \textbf{dispose :} Libera los recursos cuando se cierra la pantalla.
    \item \textbf{\_loadInitialData :} Ejecuta en paralelo la carga de los datos del hogar, productos, deudas y tareas.
    \item \textbf{\_cargarNombresUsuarios :} Obtiene a través de los IDs de los miembros del hogar, los nombres de los miembros del hogar.
    \item \textbf{\_setupTareasListener :} Escucha los cambios en las tareas del usuario y calcula cuántas tareas debe realizar hoy, cuántas tareas tiene en la semana actual y cuántas tareas tiene pendientes. 
    \item \textbf{\_setupDeudasListener :} Escucha los cambios en las deudas del usuario. Actualiza la lista de deudas no pagadas.
    \item \textbf{\_obtenerNombreHogar :} Busca el hogar al que pertenece el usuario actual y obtiene el nombre.
    \item \textbf{\_obtenerProductosUsuario :} Busca y carga hasta 5 productos que pertenece a la lista de compra donde participa el usuario. 
    \item \textbf{\_obtenerDeudasPendientes :} Carga las 3 deudas que afectan al usuario, ya sea como deudor o acreedor. También obtiene los nombres de las personas implicadas.
    \item \textbf{\_buildAppBar :} Construye la barra superior de la pantalla, donde se muestra el nombre del hogar y el botón del perfil. 
    \item \textbf{\_buildLoadingIndicator : } Muestra un indicador de carga mientras se cargan los datos iniciales.
    \item \textbf{\_buildQuickSummary :} Muestra las dos tarjetas superiores con un resumen de las tareas y el balance de deudas del usuario.
    \item \textbf{\_buildSummaryCard :} Construye una tarjeta que muestra un resumen de las tareas o deudas del usuario.
    \item \textbf{\_buildWeekSection :} Sección de planificación semanal que enlaza con el calendario. Muestra los días de la semana resaltando el día actual.
    \item \textbf{\_buildSectionHeader :} Cabecera de cada sección con opción de ver más.
    \item \textbf{\_buildWeekPlanner :} Visualiza la semana actual como una fila de días, resaltando el día de hoy.
    \item \textbf{\_buildDiaItem :} Dibuja cada día de la semana con su nombre abreviado y número.
    \item \textbf{\_buildWeekStats :} Muestra estadísticas rápidas de las tareas de hoy y de la semana. 
    \item \textbf{\_buildStatItem :} Tarjeta pequeña para cada estadística. 
    \item \textbf{\_buildDebtsSection :} Sección que muestra las deudas pendientes del usuario. Permite ver detalles y acceder a la pantalla completa de gastos. 
    \item \textbf{\_buildDebtTile :} Tarjeta que muestra un resumen de cada deuda pendiente.
    \item \textbf{\_buidShoppingListSection :} Sección que muestra los productos de la lista de la compra.
    \item \textbf{\_buildProductTile :} Tarjeta de un solo producto, mostrando su icono, nombre y cantidad.
    \item \textbf{\_buildEmptyState :} Muestra un mensaje cuando no hay datos para mostrar.
\end{itemize}

\subsubsection{Base de datos}

Como resultado de esta última iteracción, se han creado las colecciones gastos, deudas y pagos en la base de datos de Firestore. 

Para la colección de \textbf{gastos} se ha creado la siguiente estructura:

\begin{itemize}
    \item \textbf{debenPagar}: Almacena los IDs de los usuarios que deben pagar el gasto.
    \item \textbf{fecha}: Almacena la fecha en la que se ha realizado el gasto.
    \item \textbf{fechaCreacion}: Almacena la fecha en la que se ha creado el gasto.
    \item \textbf{hogarId}: Almacena el ID del hogar al que pertenece el gasto.
    \item \textbf{monto}: Almacena el monto total del gasto.
    \item \textbf{montoPorPersona}: Almacena el monto que debe pagar cada persona.
    \item \textbf{pagado}: Almacena un booleano que indica si el gasto ha sido pagado o no.
    \item \textbf{pagadorId}: Almacena el ID del usuario que ha pagado el gasto.
    \item \textbf{titulo}: Almacena el título del gasto.
\end{itemize}

La colección de \textbf{deudas} almacena la siguiente información:

\begin{itemize}
    \item \textbf{acreedor}: Almacena el ID del usuario que es el acreedor de la deuda.
    \item \textbf{creadoEn}: Almacena la fecha en la que se ha creado la deuda.
    \item \textbf{deudor}: Almacena el ID del usuario que es el deudor de la deuda.
    \item \textbf{esCompensada}: Almacena un booleano que indica si la deuda ha sido compensada o no.
    \item \textbf{fechaPago}: Almacena la fecha en la que se ha pagado la deuda en caso de que se haya pagado.
    \item \textbf{hogarId:} Almacena el ID del hogar al que pertenece la deuda.
    \item \textbf{monto}: Almacena el monto de la deuda.
    \item \textbf{pagado}: Almacena un booleano que indica si la deuda ha sido pagada o no.
    \item \textbf{ultimaActualizacion}: Almacena la fecha de la última actualización de la deuda.
\end{itemize}

Por ultimo la colección de \textbf{pagos} almacena la siguiente información:

\begin{itemize}
    \item \textbf{acreedor}: Almacena el ID del usuario que es el acreedor del pago.
    \item \textbf{deudor}: Almacena el ID del usuario que es el deudor del pago.
    \item \textbf{fecha}: Almacena la fecha en la que se ha realizado el pago.
    \item \textbf{hogarId}: Almacena el ID del hogar al que pertenece el pago.
    \item \textbf{monto}: Almacena el monto del pago.
    \item \textbf{tipo}: Almacena el tipo de pago (si es un pago o una compensación).
\end{itemize}
